## 一、真实问题分析

### 1.1 表面需求

用户原话（从 idea.txt 提取）：

> "每日打卡页面——说实话我还没有想好"

用户表达了明确的意图（需要打卡功能）但对具体设计没有预设方案。结合已确认的上下文：
- 打卡入口位于首页金刚区按钮 + 右侧边栏（已确认）
- 核心任务维度：吃好、睡好、探索花园（已确认）
- 亮点功能：家长上传便便照片 → AI 分析（已确认）
- 打卡成功给予奖励（已确认）

### 1.2 真实问题（3层Why追问）

| 层级        | 追问                             | 回答 |
| ----------- | -------------------------------- | ---- |
| 第 1 层 Why | 为什么需要每日打卡功能？         | 花园探索是"玩"的入口，但缺乏每日回访的触发机制；打卡将儿童的真实健康行为（吃、睡、探索）与虚拟花园世界连接，形成"现实行为 → 虚拟反馈"的行为强化闭环 |
| 第 2 层 Why | 为什么打卡是留存的关键？         | 3-6 岁儿童的行为养成依赖重复和即时反馈；家长也需要一个可量化的"今天我陪孩子做了什么"的确认感；没有打卡，产品沦为一次性体验 |
| 第 3 层 Why | 如果不做打卡，最严重的后果是什么？ | 用户首日留存后次日流失——花园探索缺乏"明天再来"的理由；家长失去持续使用的动力；整个产品的长期价值（消化健康追踪、饮食习惯改善）无法兑现 |

**结论**：真正要解决的问题是——**为 3-6 岁儿童及其家长构建一个"分析 → 建议 → 执行 → 再分析"的健康闭环：便便分析识别饮食问题 → 动态生成个性化打卡任务 → 家长引导执行 → 下次分析验证改善效果。** 打卡不是一次性记录工具，而是持续追踪儿童消化健康的日常锚点。

### 1.3 解法空间

| 解法 | 描述 | 优势 | 劣势 | 可行性评估 |
| ---- | ---- | ---- | ---- | ---------- |
| 方案 A：纯手动打卡 | 家长每天打开页面勾选"吃好""睡好""玩了花园"，完成后获得奖励 | 实现最简单、零依赖 | 枯燥、无验证感、易作弊、家长操作负担大 | 高（但不推荐，体验差） |
| 方案 B：混合验证打卡（推荐） |"探索花园"由系统自动检测（交互次数/时长），"吃好""睡好"由家长手动确认；预留 Apple Health 接口 | 自动化降低操作负担、手动项保留灵活度、架构可扩展 | 自动检测规则需调优（多少交互算"完成"？） | 高 |
| 方案 C：全自动健康数据打卡 | 接入 Apple Health / 智能手环，自动获取饮食、睡眠数据 | 完全无感、数据真实 | 依赖外部设备、隐私风险高、3-6岁儿童通常不佩戴设备 | 低 |

**选定方案**：**方案 B（混合验证打卡）**，理由：
- 澄清阶段已确认此方向，与平台路线（Web 桌面端优先）一致
- "探索花园"可被系统客观检测（花园场景天然产生交互数据），自动化合理
- "吃好""睡好"涉及现实世界行为，当前阶段无可行自动检测手段，手动确认为最优解
- Apple Health 接口预留为架构扩展点，不增加 MVP 复杂度

### 3.2 优先级判定

- **P0（必须支持）**：DC-01 完成打卡、DC-03 接收奖励、DC-07 花园交互自动触发。这是打卡最小闭环。
- **P1（应当支持）**：DC-02 打卡日历、DC-04 便便上传、DC-05 便便分析、DC-08 连续成就。完整打卡体验的必要组成。
- **P2（可以延后）**：DC-06 补签。体验优化项，不阻塞主流程。

## 四、业务流程梳理

### 4.1 主流程（Happy Path） — DC-01 完成每日打卡

| 步骤 | 操作者 | 动作 | 系统判断 | 输入 | 输出 | 状态变化 |
| ---- | ------ | ---- | -------- | ---- | ---- | -------- |
| 1 | 家长/儿童 | 从首页金刚区点击「每日打卡」或右侧边栏打卡入口进入 | 是否当日首次进入？是 → 展示今日任务列表 | 点击事件 | 打卡页面（今日任务列表） | 页面加载，读取当日任务状态 |
| 2 | 系统 | 检查"探索花园"任务状态 | 今日花园交互次数 ≥ 阈值（如 ≥ 3 次投喂/探索操作）→ 自动标记完成 | 花园行为日志 | "探索花园"任务显示 ✅ 已完成 | 任务 1/3 完成 |
| 3 | 家长 | 确认"吃好"任务 — 点击「确认完成」按钮。任务内容由便便分析结果动态决定：未分析时展示默认"今天吃好了吗？"，分析后替换为具体建议（如"今天多吃蔬菜"） | 无（信任家长输入） | 点击事件 | "吃好"任务显示 ✅ 已完成 | 任务 2/3 完成 |
| 4 | 家长 | 确认"睡好"任务 — 点击「确认完成」按钮 | 无（信任家长输入） | 点击事件 | "睡好"任务显示 ✅ 已完成 | 任务 3/3 完成 |
| 5 | 系统 | 三项任务全部完成 → 触发打卡成功 | 当日全部任务状态 = 已完成 | 任务完成状态 | 全屏庆祝动画 + 奖励弹出（星星/徽章进度） | 当日打卡状态：未完成 → 已完成 |
| 6 | 系统 | 更新连续打卡天数、更新徽章进度、联动花园状态（如花园中出现今日打卡纪念小物件） | 连续天数 +1；检查是否触发里程碑 | 打卡记录 | 连续天数更新、可能的新徽章 | 打卡日历当日标记为已完成 |

### 4.2 状态机

```
          ┌──────────────────┐
          │   当日未打卡      │ ← 每日 00:00 重置
          └────────┬─────────┘
                   │
     ┌─────────────┼─────────────┐
     │ 系统自动检测  │             │ 家长手动确认
     │ "探索花园"   │             │ "吃好"/"睡好"
     ▼             │             ▼
┌─────────┐       │      ┌─────────┐
│ 部分完成 │◄──────┼─────►│ 部分完成 │
│ (1/3)   │       │      │ (1-2/3) │
└────┬────┘       │      └────┬────┘
     │            │            │
     └────────────┼────────────┘
                  │ 全部任务完成 (3/3)
                  ▼
          ┌──────────────┐
          │  打卡已完成   │ → 触发奖励动画 + 连续天数 +1
          └──────────────┘
```

| 当前状态 | 触发事件 | 目标状态 | 条件/约束 |
| -------- | -------- | -------- | --------- |
| 当日未打卡 | 系统检测到花园交互达阈值 | 部分完成（探索花园 ✅） | 当日花园交互次数 ≥ 3 次 |
| 当日未打卡 | 家长点击确认"吃好" | 部分完成（吃好 ✅） | 家长身份验证通过 |
| 当日未打卡 | 家长点击确认"睡好" | 部分完成（睡好 ✅） | 家长身份验证通过 |
| 部分完成（1-2/3） | 剩余任务全部完成 | 打卡已完成 | 三项任务全部标记完成 |
| 打卡已完成 | 次日 00:00 | 当日未打卡 | 系统自动重置（cron 或首次访问触发） |
| 任何状态 | 当日结束（23:59:59）后 | 锁定（不可再修改当日状态） | 保留当日最终快照 |

### 4.3 其他场景流程

**DC-02 查看打卡日历**：
- 打卡页面顶部展示当月日历网格
- 已打卡日期显示绿色圆点 + 花园小图标（根据当日便便分析结果变化）
- 未打卡日期显示灰色
- 今日高亮边框
- 点击历史日期可查看当日打卡详情（完成任务 + 便便分析结果摘要）

**DC-04/05 便便上传、分析 → 动态任务生成闭环**（与主流程差异）：

| 步骤 | 操作者 | 动作 | 系统判断 | 输出 |
| ---- | ------ | ---- | -------- | ---- |
| 1 | 家长 | 在打卡页面点击「便便分析」入口 | 当日是否已上传？是 → 展示分析结果 | 上传界面或历史结果 |
| 2 | 家长 | 拍照或从相册选择照片 | 格式校验（JPEG/PNG/HEIC）+ 大小校验（≤10MB，自动压缩） | 上传进度条 |
| 3 | 系统 | 调用第三方 API 分析 | 图片内容是否为粪便？否 → 提示重新上传 | 分析中状态（spinner + "菌小园正在观察便便…"） |
| 4 | 系统 | 接收分析结果，映射为饮食诊断 | 根据粪便特征识别潜在饮食问题（缺水/缺纤维/高脂等），查询诊断→任务映射表 | 饮食诊断结果 + 对应建议任务文案 |
| 5 | 系统 | 将今日"吃好"任务替换为具体建议 | 当日"吃好"未确认 → 更新任务文案；已确认 → 提示"明天的饮食建议已更新" | 打卡页面"吃好"任务变为具体建议（如"今天多吃一份蔬菜 🥬"），旁边出现"跳过"按钮 |
| 5a | 家长 | （可选）点击"跳过"→ 选择原因 | 弹出原因选择："今天已吃过""孩子过敏/不爱吃""我觉得不需要" | 任务恢复默认文案"今天吃好了吗？"，跳过记录写入日志 |
| 6 | 家长 | 按具体建议引导孩子完成，回到打卡页确认 | 同主流程步骤 3 | — |
| — | 系统 | 分析结果有效期管理 | 最近一次分析距今 >3 天 →"吃好"任务自动恢复默认文案；打卡页提示"便便分析已过期，上传新照片获取最新建议～" | 任务文案回退 |

**诊断 → 任务映射表（基于布里斯托大便分类法，Bristol Stool Scale）**：

| 布里斯托类型 | 粪便特征 | 饮食诊断 | 动态任务文案 |
| ------------ | -------- | -------- | ------------ |
| Type 1 | 分散硬块，坚果状，难排出 | 严重便秘，水分和膳食纤维严重不足 | "今天多喝三杯水 💧 + 吃一份蔬菜 🥬" |
| Type 2 | 香肠状但表面凹凸不平、硬结 | 轻度便秘，水分摄入不足 | "今天多喝两杯水 💧" |
| Type 3 | 香肠状，表面有裂痕 | 正常偏干，基本健康但可优化 | "今天吃一份蔬菜 🥬，让便便更顺畅～" |
| Type 4 | 光滑柔软，蛇形，易排出 | 饮食均衡，消化健康 | "今天吃得很棒，继续保持！🌟"（鼓励型） |
| Type 5 | 软块状，边缘清晰，易排出 | 膳食纤维可能不足 | "今天吃一份蔬菜 + 一个水果 🥬🍎" |
| Type 6 | 糊状/蓬松状，边缘参差不齐 | 轻度腹泻/消化不良 | "今天少吃生冷食物，多喝温水 🍵" |
| Type 7 | 水样状，完全无固体 | 严重腹泻，需关注 | "今天注意清淡饮食，多补充水分 ⚠️"（建议就医提示） |

> **设计说明**：
> - Type 3/4 为正常范围，任务文案为鼓励或轻度优化建议
> - Type 1/2/5/6 为轻度偏离，给出具体饮食调整建议
> - Type 7 为需关注信号，除饮食建议外附加"如持续出现建议咨询医生"的温和提示
> - 便便分析结果同时联动花园状态：Type 1-2 → 花园干旱；Type 5-7 → 花园溪流泛滥；Type 3-4 → 花园水润平衡 |

**DC-08 连续打卡里程碑**：

| 里程碑 | 触发条件 | 奖励 |
| ------ | -------- | ---- |
| 初露锋芒 | 连续 3 天 | 花园中出现"打卡小旗帜"装饰物 |
| 持之以恒 | 连续 7 天 | 特殊徽章"一周之星" + 花园角色集体欢呼动画 |
| 养成习惯 | 连续 30 天 | 稀有徽章"月度冠军" + 解锁隐藏花园区域 |
| 肠道守护者 | 连续 100 天 | 传说徽章 + 花园永久夜景烟花特效 |

## 五、异常和边界场景

### 5.1 异常场景清单

| 编号 | 类别 | 异常场景 | 触发条件 | 预期系统行为 | 影响范围 |
| ---- | ---- | -------- | -------- | ------------ | -------- |
| DC-EX-01 | 用户操作 | 家长重复点击"确认完成" | 同一任务已确认后再次点击 | 按钮置灰不可重复点击，Toast 提示"已确认过啦～" | 打卡确认按钮 |
| DC-EX-02 | 用户操作 | 家长在非当日尝试确认昨日任务 | 系统时间已过 23:59:59 | 提示"这是昨天的任务哦，需要补签吗？"→ 引导补签流程 | 打卡确认逻辑 |
| DC-EX-03 | 用户操作 | 儿童误触家长确认按钮 | 儿童使用中点击"吃好/睡好"确认 | 弹出家长验证（简单算术题如"3+5=?"），验证通过才执行确认 | 打卡页面 |
| DC-EX-04 | 系统状态 | 花园行为日志丢失/延迟 | 系统检测"探索花园"时无日志记录 | 降级为手动确认模式：打卡页"探索花园"任务显示手动确认按钮 | 自动检测逻辑 |
| DC-EX-05 | 数据 | 连续打卡天数计算错误（跨时区/手动改时间） | 用户修改设备系统时间 | 使用服务端时间为准；检测到时间异常时标记但不中断打卡 | 连续天数统计 |
| DC-EX-06 | 数据 | 便便图片过大/非粪便内容 | 上传 >10MB 或 AI 识别非粪便 | 压缩或提示"请上传便便照片哦"；记录异常上传次数 | 便便分析模块 |

| DC-EX-08 | 并发 | 家长在两个设备同时确认不同任务 | 手机 + 平板同时操作 | 乐观锁合并，最后写入的服务端时间戳为准；两项确认均生效 | 打卡状态 |
| DC-EX-09 | 后台处理 | 便便分析 API 超时/不可用 | API 响应 >30s 或服务宕机 | 先返回"分析中"状态；30s 超时后展示降级文案"菌小园今天有点累，稍后再来看看分析结果吧～"；支持手动重试 | 便便分析 |
| DC-EX-10 | 历史数据 | 打卡规则变更（如任务数量从 3 项变为 5 项） | 版本更新后新旧规则不一致 | 历史打卡记录保留原规则标记；新规则仅应用于变更后的日期 | 打卡日历 |
