## 一、真实问题分析

### 1.1 表面需求

用户原话（从 idea.txt 提取）：

> "系统的宗旨：寓教于乐 通过有趣的交互 丰富的场景故事 并且通过打卡奖励 甚至通过小孩最后排出的排泄物的图片判断小孩的膳食以及给出膳食建议 让小孩得到对肠道消化流程的科普教育"

构建一个面向 0-8 岁儿童及其家长的「肠道花园」系统——将人体消化道映射为一个卡通3D花园场景，通过场景交互、每日打卡、AI导览对话、便便图片分析等手段，让儿童在玩耍中学习消化系统科普知识，并帮助家长了解孩子的消化健康状况。

### 1.2 真实问题（3层Why追问）

| 层级        | 追问                             | 回答 |
| ----------- | -------------------------------- | ---- |
| 第 1 层 Why | 为什么需要这个功能？             | 儿童缺乏直观、有趣的渠道了解消化系统运作原理；家长缺少一种不依赖说教的方式来引导孩子关注身体健康 |
| 第 2 层 Why | 为什么这个问题现在必须解决？     | [待确认] 用户未在 idea.txt 中说明紧迫性来源——可能是个人创业想法、观察到市场空白、或自身育儿中的痛点 |
| 第 3 层 Why | 如果不解决，最严重的后果是什么？ | 儿童对自身消化健康缺乏基本认知，可能延续不良饮食和生活习惯；家长错过早期健康教育的窗口期 |

**结论**：真正要解决的问题是——**为 0-8 岁儿童家庭提供一种沉浸式、游戏化的消化健康科普工具，降低健康教育的门槛和枯燥感，同时让家长能便捷地追踪孩子的消化状态。**

### 1.3 解法空间

| 解法                           | 描述 | 优势 | 劣势 | 可行性评估 |
| ------------------------------ | ---- | ---- | ---- | ---------- |
| 方案 A（用户提议）：完整 App   | 包含 3D 花园场景、AI 导览、打卡系统、便便分析、徽章系统的独立应用 | 体验完整、交互丰富、品牌感强 | 开发成本高、周期长、需 AI 能力 | 中（需组建团队或外包） |
| 方案 B：MVP 渐进式             | 先上线核心场景交互 + 打卡，AI 导览和便便分析用简化方案替代，后续迭代 | 快速验证、成本可控、风险低 | 初期体验不完整，可能影响用户留存 | 高 |
| 方案 C：微信小程序轻量版       | 基于微信生态，利用小程序能力，降低获客成本 | 家长无需下载、社交传播便利 | 3D 性能受限、受平台规则约束 | 中高 |

**选定方案**：**MVP 渐进式 + 三步走平台路线**。

| 阶段 | 平台 | 目标 |
| ---- | ---- | ---- |
| Phase 1 | Web 电脑端 | 桌面浏览器优先，利用 PC 端 GPU 性能充裕的优势，先验证核心 3D 花园交互和打卡闭环 |
| Phase 2 | 微信小程序 | 移动端覆盖，借微信生态降低获客成本，适配小程序的性能约束和交互模式 |
| Phase 3 | 原生 App（iOS + Android） | 完整体验，3D 性能最优，支持离线、推送等高级能力 |

选择理由：
- 用户明确表示每日打卡页面和成长徽章页面"还没有想好"，说明需求成熟度未达到完整开发阶段
- 核心差异化场景（3D 花园交互）在桌面 Web 端（Three.js + WebGL 2.0）可优先验证，技术风险最低
- AI 导览和便便分析涉及较高的技术不确定性，适合在 MVP 后根据真实数据迭代
- 各阶段代码架构应保持共享核心逻辑层（状态机、数据模型、API），仅表现层按平台适配

## 二、用户角色分析

### 2.1 角色清单

| 角色       | 使用目标 | 关注信息 | 使用频率 |
| ---------- | -------- | -------- | -------- |
| 儿童用户（**MVP 聚焦 3-6 岁**） | 在花园中玩耍、与角色互动、触发动画和科普小知识、收集徽章 | 花园里发生了什么变化？我获得了什么新徽章？角色们今天是什么状态？ | 每天（家长引导下） |
| 家长 | 引导孩子完成每日任务、上传便便照片获取分析、查看孩子的消化报告和膳食建议、管理孩子的使用时长 | 孩子的消化状态如何？今天的饮食有什么建议？孩子学到了什么？ | 每天（检查打卡+报告） |
| 系统/AI 导览「菌小园」 | 回答用户问题、引导探索、讲解科普知识、预警花园"异常状态" | —（系统角色） | 持续在线 |

> **年龄分层策略**：MVP（Phase 1）聚焦 **3-6 岁** 学龄前儿童——该年龄段已具备基本触控/鼠标操作能力，对卡通角色有天然亲近感，且是饮食习惯形成的关键窗口期。
> - 0-2 岁（婴幼儿）：Phase 2 扩展，交互模式为"家长全权操作 + 儿童观看"，内容以感官刺激为主
> - 6-8 岁（小学低年级）：Phase 2/3 扩展，增加更高阶科普内容、文字阅读比例和复杂问答
>
> [待确认] 是否需要额外角色，如：内容管理员（管理科普内容/题库）、医生/营养师（专业审核 dietary advice）

**账号体系设计（已确认）**：

- 家长通过 **手机号+验证码** 注册为主账号，拥有数据控制权（查看、导出、删除儿童数据）
- 儿童作为家长账号下的 **"档案"（Profile）** 存在（昵称 + 年龄），无需独立登录
- 支持一个家长账号下创建多个儿童档案（多孩家庭场景）
- 家长可为每个儿童档案设置：使用时长限制、隐私偏好
- 所有儿童数据存储在家长账号下，家长可随时删除
- 合规基础：符合《儿童个人信息网络保护规定》中"征得监护人同意"的要求；后续 Phase 需补充 COPPA 合规（如进入美国市场）

## 三、使用场景拆解

### 3.1 场景清单

| 编号  | 场景名 | 触发条件 | 频率 | 优先级 | 说明 |
| ----- | ------ | -------- | ---- | ------ | ---- |
| SC-01 | 花园自由探索 | 儿童打开「探索花园」页面，自由浏览场景、点击角色触发动画/科普 | 高 | **P0** | 核心体验，系统存在的基础 |
| SC-02 | 食物投喂交互 | 儿童在花园中选择不同食物"投喂"，观察花园和角色的状态变化 | 高 | **P0** | 核心交互机制，直接承载教育目标 |
| SC-03 | AI导览对话 | 用户在首页或花园中通过打字/语音向菌小园提问 | 高 | **P0** | 首页AI sidebar为一级入口 |
| SC-04 | 每日打卡 | 家长引导孩子完成每日任务（吃好/睡好/探索花园等），确认完成获得奖励 | 高 | **P0** | 用户保留的关键机制 |
| SC-05 | 便便图片分析 | 家长拍摄/上传孩子便便照片，系统分析并给出粪便健康反馈和饮食建议 | 中 | **P1** | 系统的亮点功能（用户原话），但技术不确定性高 |
| SC-06 | 天气/状态变化观察 | 系统根据"天气"状态（如熬夜、压力大）改变花园生态表现，用户观察并尝试"治疗" | 中 | **P1** | 与SC-02关联，体现身体健康对肠道的影响 |
| SC-07 | 放大镜科普 | 儿童使用放大镜点击花园中某个器官区域，弹出对应科普视频/动画 | 中 | **P1** | 教育功能的重要载体 |
| SC-08 | 每日问答 | 儿童在首页点击"每日问答"按钮，跳转花园并弹出问答题 | 中 | **P1** | 结合花园场景的轻量学习检验 |
| SC-09 | 查看成长徽章 | 家长/儿童查看已获得徽章、待获得徽章、成长报告 | 中 | **P1** | 激励系统的展示载体 |
| SC-10 | 花园"治疗"交互 | 当花园出现异常状态（如坏菌泛滥、干旱），用户采取措施恢复健康生态 | 低 | **P2** | 与SC-02/SC-06形成完整闭环，体验优化 |
| SC-11 | 设置管理 | 家长进行账号设置、隐私管理、使用时长限制等 | 低 | **P1** | 基础功能，合规要求 |

### 3.2 优先级判定

- **P0（必须支持）**：SC-01 花园探索、SC-02 食物投喂交互、SC-03 AI导览对话、SC-04 每日打卡。这四项是系统能运转的最小闭环。
- **P1（应当支持）**：SC-05 便便分析、SC-06 天气状态、SC-07 放大镜科普、SC-08 每日问答、SC-09 成长徽章、SC-11 设置管理。这些是系统差异化和完整的必要组成。
- **P2（可以延后）**：SC-10 花园治疗交互。锦上添花的体验深化，可在主流程跑通后迭代。

## 四、业务流程梳理

### 4.1 主流程（Happy Path）

**SC-01 + SC-02 核心探索交互流程**：

| 步骤 | 操作者 | 动作 | 系统判断 | 输入 | 输出 | 状态变化 |
| ---- | ------ | ---- | -------- | ---- | ---- | -------- |
| 1 | 儿童/家长 | 从首页点击「食物旅行地图」进入探索花园 | 用户是否首次进入？是 → 播放引导动画 | 点击事件 | 全屏花园场景 | 花园默认状态（完美健康生态） |
| 2 | 儿童 | 点击食物栏中的某类食物（如高糖零食）拖入花园 | 食物类型匹配 → 触发对应生态反应 | 食物类型ID | 场景动画变化（如坏菌膨胀、溪流变浊） | 花园状态切换：健康 → 高糖高脂入侵 |
| 3 | 系统 | 角色们根据新状态播放对应动画（菌小园焦急预警、纤纤种子被黏液淹没、杂草坏菌膨胀等） | — | 当前花园状态 | 角色动画+科普语音/文字 | 多角色同步切换到对应状态 |
| 4 | 儿童 | 投喂"纤维种子"到发酵工坊区域 | 种子落入风车蘑菇房范围 → 触发发酵动画 | 投喂位置+种子类型 | 风车转动、金色丁丁泉灵产出 | 花园逐步恢复，发酵工坊→活跃状态 |
| 5 | 系统 | 调节泥土水分回收营地排水闸门（或自动/手动操作），便便小船顺利驶出 | 当前花园水分平衡度在正常范围 | 水分数据 | 香蕉小船戴着红领结顺畅驶出 | 一次完整消化循环完成 |
| 6 | 系统 | 弹出科普小卡片"恭喜！你帮助肠道完成了一次健康的消化！" | — | 循环完成信号 | 科普知识+可能的徽章进度 | 返回健康状态 |

### 4.2 状态机

```
                   ┌──────────────┐
                   │ 完美健康生态  │ ← 默认初始状态
                   └──────┬───────┘
                          │
          ┌───────────────┼───────────────┐
          │ 投喂高糖食物  │               │ 投喂干硬食物
          ▼               │               ▼
 ┌────────────────┐       │      ┌────────────────┐
 │ 高糖高脂入侵   │       │      │ 有菜无水干旱   │
 │ 坏菌膨胀       │       │      │ 种子干硬       │
 │ 溪流油污       │       │      │ 溪流干涸       │
 └───────┬────────┘       │      └───────┬────────┘
         │                │              │
         │ 投喂纤维+水分  │              │ 补充水分
         ▼                │              ▼
 ┌────────────────┐       │      ┌────────────────┐
 │ 恢复中         │       │      │ 恢复中         │
 └───────┬────────┘       │      └───────┬────────┘
         │                │              │
         └────────────────┼──────────────┘
                          │ 平衡恢复
                          ▼
                   ┌──────────────┐
                   │ 完美健康生态  │
                   └──────────────┘
```

| 当前状态 | 触发事件 | 目标状态 | 条件/约束 |
| -------- | -------- | -------- | --------- |
| 完美健康生态 | 用户投喂高糖高脂食物 | 高糖高脂入侵 | 投喂物被识别为高糖高脂类别 |
| 完美健康生态 | 用户投喂干硬食物 + 水分不足 | 有菜无水干旱 | 投喂物为干燥类且水分值低于阈值 |
| 高糖高脂入侵 | 用户投喂纤维种子 + 补充水分 | 恢复中 | 投喂物为纤维类且持续补充水分 |
| 有菜无水干旱 | 用户补充水分 | 恢复中 | 水分补给达到阈值 |
| 恢复中 | 水分平衡 + 排便动画完成 | 完美健康生态 | 水分值在正常范围且便便小船正常驶出 |

> [待确认] 上述三类状态（完美/高糖高脂/干旱）来自 idea.txt 的角色状态表，但用户是否计划设计更多状态（如"过度用药"、"肠道菌群失调"等）尚未明确。

## 五、异常和边界场景

### 5.1 异常场景清单

| 编号 | 类别 | 异常场景 | 触发条件 | 预期系统行为 | 影响范围 |
| ---- | ---- | -------- | -------- | ------------ | -------- |
| EX-01 | 用户操作 | 儿童连续点击/拖拽过快导致动画堆积 | 低龄儿童无意识连续操作 | 动画队列机制，限制同时播放数；连续操作时跳过中间动画直接到最终状态 | 花园场景渲染 |
