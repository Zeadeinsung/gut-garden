### 会话 2026-07-30

- Q: 便便分析方案选择（拍照API分析 vs 图标选择本地存储 vs 双模式共存）？ → A: 双模式共存——默认图标选择模式（零门槛 + local-first），可选拍照上传模式（高级功能，需注册），两种模式并存，用户渐进升级
- Q: 花园交互深度与视觉风格选择（纯3D vs 纯2D vs 渐进式增强 vs 2D为主3D点缀）？ → A: 2D为主 + 3D点缀——整体 2D 手绘童话风（森林绿 #4E6A3E + 奶油米 #FFF9EF + 珊瑚粉 #F38D83），仅在"探索花园"核心页面使用轻量 3D 场景（简化版 Three.js，MVP 先做 2-3 个核心角色），降低整体 3D 资源投入
- Q: 每日打卡任务结构（3项 vs 6项 vs 3主项+附加项）？ → A: 3 主项 + 附加项——核心 3 项不变（探索花园自动检测 + 吃好动态 + 睡好手动），吃好/睡好确认时弹出可选子项（喝水/蔬菜/水果/户外活动），勾选可额外加分但不强制
- Q: 徽章与激励体系（4类×18-20枚+三级稀有度 vs 6阶段线性 vs 融合方案）？ → A: 融合方案——外部 6 阶段作为"花园成长主线"（种子→幼苗→成长→丰收→大师→终极），替代花园等级 Lv.1-10；己方 4 大分类徽章作为"支线收集"（坚持之星/探索达人/科普小学者/特殊成就），每枚保留铜→银→金三级升级
- Q: 叙事隐喻与科普内容体系（器官隐喻 vs 生态隐喻 vs 融合）？ → A: 完全切换为外部生态隐喻——肠道 = 花园生态，微生物 = 居民，食物 = 养分。吸收外部 5 大知识模块体系（膳食纤维广场/发酵工坊/短链脂肪酸泉/肠道屏障城墙/生态平衡观测站），复用已有知识卡片 PSD 素材
- Q: 账号体系（游客 vs 注册）？ → A: 游客友好 + 渐进注册——游客可直接使用花园探索、探索课堂、便便图标选择、每日打卡（全部 localStorage）。仅在便便拍照分析/创建儿童档案/查看成长报告/跨设备同步时触发注册。注册后 localStorage 数据自动迁移到后端
- Q: 目标年龄范围（3-6 vs 3-10）？ → A: 扩展至 3-10 岁——一套设计覆盖全年龄段，大字体+简短文案适用低龄，详细科学注释适用高龄，利用双阅读层级自然适配不同年龄段
- Q: 首页信息架构（桌面金刚区 vs 移动导航+浮动按钮）？ → A: 桌面端金刚区——首页 4 按钮金刚区 + 右侧 AI 边栏常驻 + 独立打卡页面，Phase 1 桌面 Web 优先，移动端适配延至 Phase 2 小程序
- Q: 正向强化与补签机制？ → A: 正向强化 + 安全网——核心哲学采用正向强化（断了不惩罚、不降级、不标红），保留补签 3 次/月作为安全网。连续天数中断时温和提示"新的一轮开始了！"。徽章只看累计，里程碑仅奖励达到过的最高连续天数
- Q: AI角色设定与用户引导内容？ → A: 全面吸收外部内容——AI回答风格指南（7条规则）、AI角色设定（菌小园人格+语气）、四步引导遮罩流程、关键文案（品牌/免责/引导语）全量纳入PRD

## 1. 背景与目标

### 1.1 产品愿景

以"肠道花园"为核心生态隐喻：肠道 = 一座生机勃勃的花园，微生物 = 花园里的居民，食物 = 浇灌花园的养分。将专业的肠道微生态科学知识转化为可看、可玩、可交互的科普体验，让 3-6 岁儿童在玩耍中学习消化健康知识，同时帮助家长追踪孩子的消化健康状况。

**品牌 Slogan**：每一口食物，都在浇灌你的微观生态

**核心叙事主线**：
1. 问题引入：你的肠道里住着万亿个微小居民，它们组成了一座花园
2. 花园认知：膳食纤维是它们的食物，不同食物喂养不同居民
3. 花园运转：居民发酵纤维产生短链脂肪酸——滋养肠道屏障的"魔法养分"
4. 花园变化：饮食单一、熬夜、滥用抗生素会让花园"天气"变差，但每天都可以修复它
5. 花园观察：便便是花园寄来的"天气报告"，每日记录就能读懂信号
6. 花园行动：多喝一杯水、多吃一种蔬菜、早睡半小时——浇灌你的肠道花园

### 1.2 核心问题

儿童缺乏直观、有趣的渠道了解消化系统运作原理；家长缺少一种不依赖说教的方式来引导孩子关注身体健康。

### 1.3 产品目标

- **寓教于乐**：通过花园交互、食物投喂等游戏化手段传递消化健康知识
- **行为养成**：通过每日打卡和徽章激励，建立"分析→建议→执行→再分析"的健康习惯闭环
- **家长安心**：通过便便分析和成长报告，让家长便捷掌握孩子的消化健康趋势

### 1.4 MVP 范围（Phase 1）

| 模块 | 包含 | 不含 |
| ---- | ---- | ---- |
| 花园探索 | 2D 手绘童话风全景 + 探索页轻量 3D 场景（2-3 核心角色，食物投喂交互）、场景分层渲染 | 完整 8 角色 × 全状态动画、天气/状态系统全量 |
| 探索课堂 | 5 大知识模块（膳食纤维广场/发酵工坊/短链脂肪酸泉/肠道屏障城墙/生态平衡观测站）、知识卡片翻转交互、3 种类型选择题、90 秒科普动画（复用已有 PSD 素材） | 自定义知识库管理后台 |

## 4. 详细设计

### 4.1 花园探索

> **设计原则**：统一采用"家长深度模式 + 儿童简易模式"双阅读层级。同一页面中，科学注释、详细数据默认折叠（家长可展开），儿童看到的是主视觉 + 简短文案 + 大按钮。

#### 核心交互：食物投喂 → 生态反应

| 投喂食物类型 | 花园状态变化 | 角色反应 | 恢复方式 |
| ------------ | ------------ | -------- | -------- |
| 高糖高脂食物（蛋糕/糖果） | 坏菌膨胀、溪流油污、场景色调变暗 | 菌小园焦急预警、纤纤种子被黏液淹没、杂草坏菌膨胀大笑 | 投喂纤维种子 + 补充水分 |
| 干硬食物（饼干/坚果）+ 缺水 | 种子干硬、溪流干涸、土地龟裂 | 纤纤种子变灰、丁丁泉灵躲藏、香蕉小船搁浅 | 补充水分 |
| 纤维种子（蔬菜/水果）+ 水分 | 风车转动、金色泉灵产出、场景恢复明亮 | 菌小园欢呼、纤纤种子翠绿、香蕉小船顺畅驶出 | —（本身就是恢复行为） |

#### 状态机

```
完美健康生态 ←→ 高糖高脂入侵 → 恢复中 → 完美健康生态
    ↕
有菜无水干旱 → 恢复中 → 完美健康生态
```

### 4.2 探索课堂

基于已有 20 张知识卡片 PSD 素材，整合为 5 大知识模块的结构化"花园知识体系"。

#### 五大知识模块

| 模块名称 | 花园隐喻 | 核心知识点（3-4条/模块） | 素材状态 |

#### "便便分析 → 动态任务"闭环（双模式）

**模式一（默认）：图标选择 + 本地反馈（零门槛）**

### 4.5 AI 导览「菌小园」

#### AI 角色设定

- **名称**: 菌小园（取自"菌"和"花园"）
- **人格**: 亲切、好奇、懂科学的"花园小导游"，知道很多肠道知识但从不摆架子
- **语气**: 使用花园相关比喻、语速适中、不打断用户、不确定时会说"这个问题我需要查查资料"
- **定位**: 将复杂的肠道科学"翻译"为儿童和家长可理解的互动体验

#### AI 回答风格指南（7 条规则）

1. **用花园隐喻开头**："这个问题就像花园里的……"
2. **先给简短结论**（一句话），再给详细解释
3. **避免绝对化表述**：不说"一定""绝对不要"
4. **复杂概念用类比**："紧密连接就像花园栅栏的扣锁"
5. **结尾加一个可操作建议**：把知识转化为行动
6. **所有科学声明标注可信来源**：点击"看科学依据"可展开参考文献
7. **超出范围引导就医**：个人诊断、药物推荐类问题回复"这个问题需要咨询医生哦"

#### AI 安全边界

- 所有回答末尾标注"本项目用于科学传播，不构成医疗建议"
- 医疗相关问题（用药、诊断、症状判断）引导至就医
- 敏感内容过滤
- 不支持也不暗示任何诊断能力

#### 快捷问题推荐（6-8 个常见气泡）

预设高频问题供用户一键点击：为什么要慢慢吃饭？/ 肠道里的好菌喜欢什么？/ 酸奶对肠道有好处吗？/ 为什么吃多了会肚子疼？/ 一天要喝多少水？/ 益生菌是什么？/ 为什么放屁会臭？/ 吃辣椒会伤胃吗？

## 5. 产品规则与异常处理

### 5.1 关键业务规则

| 规则编号 | 规则 | 说明 |
| -------- | ---- | ---- |
| R01 | 每日打卡窗口基于服务端 UTC 日期，不使用客户端本地时间 | 防止用户修改设备时间作弊 |
| R02 | 补签不中断连续天数计算，每月限 3 次；连续中断不做负向惩罚（不降级、不标红），温和提示"新的一轮开始了" | 正向强化 + 安全网，降低家长焦虑 |
| R03 | 便便分析结果有效期 3 天，过期后"吃好"任务恢复默认 | 保证建议的时效性 |
| R04 | 分析结果顺延至明日，不回溯已确认的当日任务 | 尊重家长操作，避免挫败 |
| R05 | 徽章发放前检查是否已获得，使用"行为事件 ID + 徽章 ID"防重 | 保证幂等性 |
| R06 | 同一行为可触发多枚徽章，动画依次播放，最多 3 个，超出静默发放 | 避免动画堆积 |
| R07 | 设置页面需家长验证（简单算术），防止儿童误操作 | 监护人控制 |
| R08 | 成长报告分母 < 5 时展示原始数字而非百分比 | 避免小样本误导 |

### 5.2 异常处理

| 场景 | 处理方式 |
| ---- | -------- |
| 儿童连续快速点击/拖拽 | 动画队列，限制同时播放数，跳过中间帧直接到最终状态 |
| 家长上传非便便图片 | AI 识别后提示"请上传便便照片"，记录异常上传次数 |
| 低端设备无法渲染 3D | 降级为 2D 静态插画模式 + 简化动画，首次启动时检测设备性能 |
| 便便图片过大或格式不支持 | 自动压缩（≤2MB），HEIC 转 JPEG，不支持格式提示 |
| AI 导览离线/弱网 | 预设 FAQ 离线可用，在线功能显示"菌小园在休息"提示 |
| 便便分析 API 超时（>30s） | 异步处理，先展示"分析中"，完成后推送；>60s 返回降级文案 + 支持重试 |
| 同一账号多设备同时操作 | 乐观锁合并，服务端时间戳最后写入生效 |
| 徽章体系版本升级 | 旧徽章保留在"经典收藏"分区，新徽章按新规则独立计算 |
| 花园行为日志丢失 | "探索花园"任务降级为手动确认模式 |
| 首次使用无历史数据 | 展示引导性空白状态 + 速赢目标提示 |

## 7. 假设与依赖

### 7.1 假设

| 假设 | 风险 |
| ---- | ---- |
| 家长愿意每天花 3-5 分钟陪同孩子完成打卡 | 如不愿投入时间，打卡留存会受影响 |
| 第三方便便分析 API 的准确率可接受（≥70%） | 如准确率过低，动态建议可能误导，需评估降级方案 |
| 3-10 岁儿童能够在家长引导下完成花园基本交互（点击、拖拽），低龄(3-6)需更多家长辅助 | 如交互门槛过高，需进一步简化 |
| 徽章和成长阶段对 3-10 岁儿童的激励效果与预期一致 | 如激励不足，需调整徽章节奏或视觉表现 |
| 布里斯托分类法是第三方 API 的标准输出格式 | 如 API 不按此标准输出，需做格式适配层 |

### 7.2 外部依赖

| 依赖 | 影响 | 备选方案 |
| ---- | ---- | -------- |
| 第三方便便分析 API | 直接影响"动态任务"闭环 | 调研 2-3 个备选 API，保留手动上传记录作为降级 |
| 3D 美术资源（角色模型/动画/场景） | 直接影响花园探索核心体验 | MVP 先做 3 个核心角色 + 2 个状态，后续迭代补充 |
| AI 导览服务（大语言模型 API） | 影响问答质量和范围 | 预设离线 FAQ 保证基本可用 |
| 科普视频/题目内容 | 影响放大镜科普和每日问答 | MVP 使用静态图文卡片替代视频 |
