# 02-产品需求说明书：肠道花园（Gut Garden）

> **版本**: v1.0
> **创建日期**: 2026-07-27
> **来源**: idea.txt + 三份业务需求分析（总需求 / 每日打卡 / 成长徽章）
> **平台路线**: Phase 1 Web 电脑端 → Phase 2 微信小程序 → Phase 3 App
> **目标用户**: 3-6 岁儿童 + 家长

---

## 1. 背景与目标

### 1.1 产品愿景

将人体消化道映射为一个卡通 3D 花园场景，让 3-6 岁儿童在玩耍中学习消化系统科普知识，同时帮助家长追踪孩子的消化健康状况。

### 1.2 核心问题

儿童缺乏直观、有趣的渠道了解消化系统运作原理；家长缺少一种不依赖说教的方式来引导孩子关注身体健康。

### 1.3 产品目标

- **寓教于乐**：通过花园交互、食物投喂等游戏化手段传递消化健康知识
- **行为养成**：通过每日打卡和徽章激励，建立"分析→建议→执行→再分析"的健康习惯闭环
- **家长安心**：通过便便分析和成长报告，让家长便捷掌握孩子的消化健康趋势

### 1.4 MVP 范围（Phase 1）

| 模块 | 包含 | 不含 |
| ---- | ---- | ---- |
| 花园探索 | 3D 场景自由浏览、食物投喂交互（3 类食物 × 3 种花园状态）、8 个角色 × 2 种状态动画、场景分层渲染 | 花园治疗交互、天气/状态系统全量 |
| AI 导览 | 文字+语音问答、预设 FAQ、建议标签引导 | 自定义知识库管理后台 |
| 每日打卡 | 3 项任务（探索花园自动检测 + 吃好/睡好手动确认）、便便分析→动态任务、打卡日历、补签（3 次/月） | Apple Health 自动同步、多交互类型权重 |
| 成长徽章 | 4 类 × 18-20 枚徽章、铜/银/金三级稀有度、花园等级 Lv.1-10、成长报告 12 项指标 | 徽章社交分享 |
| 账号系统 | 家长手机号注册、儿童档案模式（多孩支持） | 社交登录、COPPA 完整合规 |
| 设置管理 | 使用时长限制、隐私偏好、儿童档案管理 | 内容管理后台 |

## 4. 详细设计

### 4.1 花园探索

#### 核心交互：食物投喂 → 生态反应

| 投喂食物类型 | 花园状态变化 | 角色反应 | 恢复方式 |
| ------------ | ------------ | -------- | -------- |
| 高糖高脂食物（蛋糕/糖果） | 坏菌膨胀、溪流油污、场景色调变暗 | 菌小园焦急预警、纤纤种子被黏液淹没、杂草坏菌膨胀大笑 | 投喂纤维种子 + 补充水分 |
| 干硬食物（饼干/坚果）+ 缺水 | 种子干硬、溪流干涸、土地龟裂 | 纤纤种子变灰、丁丁泉灵躲藏、香蕉小船搁浅 | 补充水分 |
| 纤维种子（蔬菜/水果）+ 水分 | 风车转动、金色泉灵产出、场景恢复明亮 | 菌小园欢呼、纤纤种子翠绿、香蕉小船顺畅驶出 | —（本身就是恢复行为） |

#### 状态机

```
完美健康生态 ←→ 高糖高脂入侵 → 恢复中 → 完美健康生态
    ↕
有菜无水干旱 → 恢复中 → 完美健康生态
```

### 4.2 每日打卡

#### 任务结构（每日固定 3 项）

| 任务 | 验证方式 | 动态？ | 说明 |
| ---- | -------- | ------ | ---- |
| 探索花园 | 系统自动检测（花园交互 ≥3 次） | 否 | 降级条件：行为日志丢失时切换为手动确认 |
| 吃好 | 家长手动确认 | **是** | 默认文案"今天吃好了吗？"；便便分析后替换为具体饮食建议 |
| 睡好 | 家长手动确认 | 否 | 信任家长输入，无自动检测 |

#### "便便分析 → 动态任务"闭环

```
家长上传便便照片 → 第三方 API 分析 → 返回布里斯托类型 (1-7)
    → 查询诊断→任务映射表 → 替换今日"吃好"任务文案
    → 家长引导执行 → 下次分析验证改善
```

**布里斯托类型 → 动态任务映射**：

| 类型 | 特征 | 诊断 | 今日"吃好"任务文案 |
| ---- | ---- | ---- | ------------------ |
| Type 1 | 分散硬块，坚果状 | 严重便秘 | "今天多喝三杯水 💧 + 吃一份蔬菜 🥬" |
| Type 2 | 香肠状，表面凹凸 | 轻度便秘 | "今天多喝两杯水 💧" |
| Type 3 | 香肠状，表面裂痕 | 正常偏干 | "今天吃一份蔬菜 🥬，让便便更顺畅～" |
| Type 4 | 光滑柔软，蛇形 | 饮食均衡 | "今天吃得很棒，继续保持！🌟" |
| Type 5 | 软块状，边缘清晰 | 纤维可能不足 | "今天吃一份蔬菜 + 一个水果 🥬🍎" |
| Type 6 | 糊状/蓬松状 | 轻度腹泻 | "今天少吃生冷食物，多喝温水 🍵" |
| Type 7 | 水样状，无固体 | 严重腹泻 | "今天注意清淡饮食，多补充水分 ⚠️"（附加就医提示） |

**分析规则**：

- 推荐频率：每天 1 次（不强制）
- 结果有效期：3 天（过期恢复默认文案）
- 已确认冲突：不回溯今日，顺延至明日任务
- 家长跳过：可选原因（"已吃过""过敏""不需要"），反馈数据用于优化

#### 打卡日历

- 点击历史日期查看当日详情（完成项 + 便便分析摘要）

## 5. 产品规则与异常处理

### 5.1 关键业务规则

| 规则编号 | 规则 | 说明 |
| -------- | ---- | ---- |
| R01 | 每日打卡窗口基于服务端 UTC 日期，不使用客户端本地时间 | 防止用户修改设备时间作弊 |
| R02 | 补签不中断连续天数计算，每月限 3 次 | 平衡灵活性和激励效果 |
| R03 | 便便分析结果有效期 3 天，过期后"吃好"任务恢复默认 | 保证建议的时效性 |
| R04 | 分析结果顺延至明日，不回溯已确认的当日任务 | 尊重家长操作，避免挫败 |
| R05 | 徽章发放前检查是否已获得，使用"行为事件 ID + 徽章 ID"防重 | 保证幂等性 |
| R06 | 同一行为可触发多枚徽章，动画依次播放，最多 3 个，超出静默发放 | 避免动画堆积 |
| R07 | 设置页面需家长验证（简单算术），防止儿童误操作 | 监护人控制 |
| R08 | 成长报告分母 < 5 时展示原始数字而非百分比 | 避免小样本误导 |

### 5.2 异常处理

| 场景 | 处理方式 |
| ---- | -------- |
| 儿童连续快速点击/拖拽 | 动画队列，限制同时播放数，跳过中间帧直接到最终状态 |
| 家长上传非便便图片 | AI 识别后提示"请上传便便照片"，记录异常上传次数 |
| 低端设备无法渲染 3D | 降级为 2D 静态插画模式 + 简化动画，首次启动时检测设备性能 |
| 便便图片过大或格式不支持 | 自动压缩（≤2MB），HEIC 转 JPEG，不支持格式提示 |
| AI 导览离线/弱网 | 预设 FAQ 离线可用，在线功能显示"菌小园在休息"提示 |
| 便便分析 API 超时（>30s） | 异步处理，先展示"分析中"，完成后推送；>60s 返回降级文案 + 支持重试 |
| 同一账号多设备同时操作 | 乐观锁合并，服务端时间戳最后写入生效 |
| 徽章体系版本升级 | 旧徽章保留在"经典收藏"分区，新徽章按新规则独立计算 |
| 花园行为日志丢失 | "探索花园"任务降级为手动确认模式 |
| 首次使用无历史数据 | 展示引导性空白状态 + 速赢目标提示 |

### 5.3 边界值

| 字段 | 范围/限制 |
| ---- | --------- |
| 每日任务数量 | 固定 3 项 |
| "探索花园"自动完成阈值 | ≥3 次交互 |
| 便便照片大小 | 10KB - 10MB（自动压缩至 ≤2MB） |
| 补签次数 | 3 次/月 |
| 便便分析结果有效期 | 3 天 |
| 打卡日历回溯 | 12 个月 |
| 徽章总数（MVP） | 18-20 枚 |
| 单次行为同时触发徽章数（动画） | ≤3 枚 |
| 花园等级上限（MVP） | 10 级 |
| 年龄范围（MVP） | 3-6 岁 |

## 7. 假设与依赖

### 7.1 假设

| 假设 | 风险 |
| ---- | ---- |
| 家长愿意每天花 3-5 分钟陪同孩子完成打卡 | 如不愿投入时间，打卡留存会受影响 |
| 第三方便便分析 API 的准确率可接受（≥70%） | 如准确率过低，动态建议可能误导，需评估降级方案 |
| 3-6 岁儿童能够在家长引导下完成花园基本交互（点击、拖拽） | 如交互门槛过高，需进一步简化 |
| 徽章和等级对 3-6 岁儿童的激励效果与预期一致 | 如激励不足，需调整徽章节奏或视觉表现 |
| 布里斯托分类法是第三方 API 的标准输出格式 | 如 API 不按此标准输出，需做格式适配层 |

### 7.2 外部依赖

| 依赖 | 影响 | 备选方案 |
| ---- | ---- | -------- |
| 第三方便便分析 API | 直接影响"动态任务"闭环 | 调研 2-3 个备选 API，保留手动上传记录作为降级 |
| 3D 美术资源（角色模型/动画/场景） | 直接影响花园探索核心体验 | MVP 先做 3 个核心角色 + 2 个状态，后续迭代补充 |
| AI 导览服务（大语言模型 API） | 影响问答质量和范围 | 预设离线 FAQ 保证基本可用 |
| 科普视频/题目内容 | 影响放大镜科普和每日问答 | MVP 使用静态图文卡片替代视频 |

## 8. 范围界限

### 8.1 MVP 明确不做

- Apple Health / 智能手环自动同步（预留接口，不做实现）
- 徽章社交分享（微信/朋友圈）
- 多语言支持（仅中文）
- 便便分析管理后台
- 徽章内容管理后台
- 花园"治疗"交互（P2）
- 天气/状态系统全量（仅做 3 类食物触发的 3 种状态）
- 0-2 岁和 6-8 岁年龄段适配（仅 3-6 岁）
- App 端（仅 Web 电脑端）
- COPPA 合规（中国市场优先）

### 8.2 V2 规划方向

- 微信小程序适配
- 0-2 岁 / 6-8 岁年龄段内容适配
- Apple Health 数据接入
- 徽章分享
- 管理员后台（内容/徽章/诊断映射表配置）
- 花园治疗交互全量
- 天气/状态系统扩展

## 9. 关键实体

| 实体 | 核心属性 | 关系 |
